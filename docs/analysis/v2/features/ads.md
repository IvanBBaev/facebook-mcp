## 0. Cross-cutting decisions

### 0.1 Tier mapping (new tools)

| Tool | Tier | `requirePlanId` | Why |
|---|---|---|---|
| `facebook_boost_post` | `irreversible` | yes (implied by tier) | Creates 4 objects; rollback is lossy (deleted objects stay readable as `DELETED`); carries a legal DSA declaration and a money envelope. Nothing spends (everything `PAUSED`), so not `spend`. |
| `facebook_upload_ad_image` | `reversible` | no (plan/apply as usual) | Adds an asset to the library; `DELETE /act/adimages?hash=` dissociates it. No money. |
| `facebook_archive_ad_object` | `irreversible` | yes | ARCHIVED → only `name`/`status` editable, only exit is DELETED; API cannot unarchive. |
| `facebook_delete_ad_object` | `irreversible` | yes | DELETED is terminal. |
| `facebook_update_ad_object` + `spend_cap_minor` | raise / remove-cap path refused; raise = `spend`, lower = `irreversible`; set-from-unset = `irreversible` | yes | Raise lets more money out; lowering to below `amount_spent` stops delivery at once and is not undoable without a later spend-tier raise. |
| `facebook_get_ad_preview` | read | — | GET only. |
| `facebook_duplicate_ad_object` | `irreversible` | yes | Creates objects; copies forced `PAUSED`. Same reasoning as boost. |
| `facebook_get_ad_set_targeting` | read | — | |
| `facebook_update_ad_set_targeting` | `spend` | yes | Widening reach on a delivering ad set changes spend rate/allocation; narrowing can stop delivery. One tier for both, keep it simple. |

All irreversible/spend tools follow the existing gate: plan preview → `plan_id`
(`PLAN_TTL_MS` 5 min, single-use claim) → out-of-band confirmation (elicitation or
`confirm_token`/`FB_CONFIRM_TOKEN`) → `readState()` divergence check before and after
confirmation → `perform`. No env var bypasses this.

The ads package spec (`createAdsPackage()` in `src/tools/ads.ts:519`) keeps
`enabledByDefault: false`, `writeModeDefault: 'plan'`.

### 0.2 New setting `FB_ADS_CAMPAIGN_SPEND_CAP_MAX`

- Meaning: maximum campaign `spend_cap` (minor units of the ad-account currency,
  non-negative integer, no currency conversion — same contract as `FB_ADS_BUDGET_CEILING`).
- Required for `facebook_boost_post` (boost refuses before the wire when unset:
  "set FB_ADS_CAMPAIGN_SPEND_CAP_MAX to enable boost"). Also bounds the `spend_cap`
  edit on `facebook_update_ad_object` and the copy flow (copies inherit the cap; refuse
  duplicates of a campaign whose cap is unset or above the max — see §7).
- Refuses, never clamps (CC-ADS-7 parity).
- Must be ≥ the account's `min_campaign_group_spend_cap` at use time (read live, §5.1);
  if smaller, refuse with "your FB_ADS_CAMPAIGN_SPEND_CAP_MAX (X) is below Meta's
  minimum campaign spend cap (Y) for this account".

    `FB_ADS_BUDGET_CEILING`, so the typo detector knows it); resolve with the existing
    `resolveBudgetCeiling`-style parser (rename/generalise to `resolveMinorUnitsEnv(name, raw, err)`),
    expose as `adsCampaignSpendCapMax`.
  - `src/core/types.ts` — `Settings.adsCampaignSpendCapMax?: number` with a TSDoc line.
  - `scripts/metadata.config.mjs` (~line 421) — env row (README table is generated by

## 1. `facebook_boost_post` — paused create-chain (campaign → ad set → creative → ad)

### 1.1 User story
As a Page owner, I want to turn an existing Page post into a ready-to-run paid boost,
created entirely `PAUSED`, with a hard campaign spend cap and a printed worst-case
spend, so that I can review it in Ads Manager (or activate it later with
`facebook_update_ad_object status:"ACTIVE"`, spend tier) without any money moving now.

### 1.2 Input (zod sketch)
```ts
const boostPostArgs = z.object({
  ad_account_id: adAccountIdArg.optional(),          // defaults to FB_AD_ACCOUNT_ID
  page_id: pageIdArg,                                  // must be in the pages registry
  post_id: z.string().regex(/^\d+(_\d+)?$/),         // "<postId>" or "<pageId>_<postId>"; normalised to "<pageId>_<postId>"
  objective: z.enum(['OUTCOME_ENGAGEMENT', 'OUTCOME_TRAFFIC', 'OUTCOME_AWARENESS']),
  name: z.string().min(1).max(200).optional(),        // base name; default "Boost <post_id> <yyyy-mm-dd>"
  budget: z.discriminatedUnion('type', [
    z.object({ type: z.literal('daily'), amount_minor: z.number().int().positive() }),
    z.object({ type: z.literal('lifetime'), amount_minor: z.number().int().positive() }),
  ]),
  spend_cap_minor: z.number().int().positive(),       // mandatory; ≤ FB_ADS_CAMPAIGN_SPEND_CAP_MAX
  bid_strategy: z.enum(['LOWEST_COST_WITHOUT_CAP', 'LOWEST_COST_WITH_BID_CAP', 'COST_CAP']), // explicit, no default
  bid_amount_minor: z.number().int().positive().optional(), // required iff BID_CAP / COST_CAP (refine)
  start_time: z.string().datetime({ offset: true }).optional(), // default: now + 10 min
  end_time: z.string().datetime({ offset: true }).optional(),   // required for lifetime (refine); daily: optional
  targeting: z.object({
    countries: z.array(z.string().regex(/^[A-Z]{2}$/)).min(1).max(25),
    age_min: z.number().int().min(18).max(65).default(18),
    age_max: z.number().int().min(18).max(65).default(65),
  }).strict(),                                           // geo + age ONLY (03-v2-scope)
  dsa: z.object({
    payor: z.string().min(1).max(512),
    beneficiary: z.string().min(1).max(512),
  }).optional(),                                         // required when any country is EU/EEA and no account default
  ...gateArgs,                                           // apply, plan_id, confirm_token
}).strict();
```
Refinements: `age_min ≤ age_max`; `bid_amount_minor` present iff strategy ≠
`LOWEST_COST_WITHOUT_CAP`; lifetime ⇒ `end_time`; `end_time > start_time + 24h` for
daily (Meta rule); `spend_cap_minor ≥ budget.amount_minor` for lifetime.
There is **no** `status`, `special_ad_categories`, `creative_features`,
`targeting_automation` or free-form `targeting` input — those are fixed (§1.4).
The schema cannot express ACTIVE.

### 1.5 Step machine

Pure planner in `src/api/ads-create.ts`:

```ts
type BoostStep = 'campaign' | 'adset' | 'creative' | 'ad';
interface BoostPlan { accountId; currency; tag /* fbmcp:<plan8> */; steps: readonly StepSpec[]; envelope; warnings; summary }
interface StepSpec { step: BoostStep; request: (prior: CreatedIds) => JsonRequest; rollback?: (id) => JsonRequest }
interface CreatedIds { campaign?: string; adset?: string; creative?: string; ad?: string }
type StepResult = { step; status: 'created'; id } | { step; status: 'failed'; error: GraphApiError; sent: 'not_sent'|'ambiguous'|'rejected' };
interface ChainOutcome { applied: {step,id}[]; rolledBack: {step,id}[]; orphaned: {step,id?,reason}[]; failedStep?: {step, error}; complete: boolean }
export function planBoost(input, ctx: {account, post, spendCapMax, budgetCeiling}): BoostPlan   // pure, throws ValidationError on refusals
export async function runBoostChain(fbRequest, plan, hooks: {journal, signal, onStep}): Promise<ChainOutcome>
```

States: `PLANNED → CAMPAIGN → ADSET → CREATIVE → AD → DONE`; any failure enters
`ROLLBACK(i)` which walks created ids in reverse (`ad → adset → campaign`; creative is
NOT deleted, see below) and ends in `ROLLED_BACK` or `PARTIAL`.

Rules:
1. **Sequential, no retries.** Each POST is sent once. `signal` is checked before
   every step; abort before step 1 ⇒ nothing sent (`failed`). Abort mid-chain ⇒ treated
   as a failure at the next step ⇒ rollback runs (rollback ignores the abort signal,
   with its own 15 s per-call timeout — stopping halfway is worse).
2. **Outcome of a failed POST** via the existing `classifyUpdateFailure` logic (ads.ts):
   - `rejected` (Graph error body with code) — object not created; roll back the earlier ones.
   - `not_sent` (`isProvablyNotSent`) — same as rejected.
   - `ambiguous` (timeout, 5xx, status 0) — object MAY exist. **Reconcile**: one GET on the
     parent edge filtered by the plan tag:
     `GET /act_{id}/<edge>?filtering=[{"field":"name","operator":"CONTAIN","value":"fbmcp:<plan8>"}]&fields=id,name`
     (edge = campaigns / adsets / ads; creatives are found via
     `GET /act_{id}/adcreatives?fields=id,object_story_id` filtered locally). Found ⇒
     add to created ids, then roll back. Reconcile itself failing ⇒ `orphaned` entry with
     `reason:'unknown — check Ads Manager for names containing fbmcp:<plan8>'`.
3. **Rollback = `DELETE /{id}`** per created object, reverse order (ad, adset,
   campaign). Deleting the campaign alone would cascade, but explicit per-object
   deletes give a precise report and survive a cascade delay. A DELETE that fails ⇒
   try `POST /{id} status=PAUSED` is pointless (already paused) — record as `orphaned`
   with `reason:'delete failed: <msg>; it is PAUSED and will not spend'`.
4. **Creative is never rolled back.** `POST adcreatives` with an existing
   `object_story_id` is idempotent (returns the existing creative), so a delete could
   remove a creative that pre-existed and is used by other ads. It is reported as
   `applied` with a note "creative kept (shared/idempotent, does not spend)". Plan
   preview states this.
5. **Name tag.** Every object name ends with ` [fbmcp:<first 8 of plan_id>]` — makes
   reconcile and orphan cleanup searchable. No PII in the tag.
6. **Divergence.** `readState()` for the gate = `{accountStatus, currency,
   minCampaignSpendCap, postEligible, defaultDsa}`; plan → confirm → apply must match.
   Currency change between plan and apply ⇒ refuse (amounts would be reinterpreted).

### 1.6 Pre-wire refusals (plan time, before any request exists)
- `FB_ADS_CAMPAIGN_SPEND_CAP_MAX` unset ⇒ refuse.
- `spend_cap_minor > FB_ADS_CAMPAIGN_SPEND_CAP_MAX` ⇒ refuse (no clamp).
- `spend_cap_minor < min_campaign_group_spend_cap` ⇒ refuse with Meta's minimum (≈US$100 equivalent).
- `spend_cap_minor` = sentinel / ≥ 2^53 ⇒ refuse.
- Budget > `FB_ADS_BUDGET_CEILING` ⇒ refuse (existing `enforceCeiling`).
- `daily amount_minor < min_daily_budget` ⇒ refuse with Meta's value.
- Any EU/EEA country (frozen list: 27 EU + IS, LI, NO — DSA "associated territories" scope is **PROBE**; be inclusive)
  and neither `dsa` input nor both `default_dsa_payor`/`default_dsa_beneficiary` ⇒ refuse,
  quoting `dsa_recommendations` if available. Passing only one default does not fill the other (verified).
- Page not in registry / post not on that Page ⇒ refuse.
- Account not serving ⇒ `adAccountBlockedError` (at-risk accounts refused too: create is not `stopsDelivery`).
- Lifetime budget > spend_cap ⇒ warning ("spend cap stops it first"), not refusal.

### 1.7 Plan preview contents (summary + warnings)
- One line per step with method + path + the human-relevant params.
- Money envelope: "At most <per_day> per day, <per_week> per 7 days; total can never exceed the
  campaign spend cap of <cap> (<currency>)". Daily flex 1.75× explained once.
- Fixed settings block: `PAUSED`, special categories NONE, explicit bid strategy, Advantage+
  enhancements OPT_OUT, Advantage+ audience off, DSA payor/beneficiary values (they are
  legal declarations — shown verbatim).
- Warnings: "Nothing spends until you activate the campaign (separate spend-tier call)";
  "If a step fails, already-created objects are deleted (they stay visible as DELETED in Ads
  Manager)"; "The creative is kept"; preview iframe valid 24 h; ad review starts only on
  activation (**PROBE** — ads created PAUSED may still enter review).
- `notPerformedNotice`: "No ad objects were created."

### 1.8 Journal entries
The gate appends one summary entry after `perform` (outcome from `classifyResult`).
The chain additionally appends per-step entries through `ctx.journal.append(...)`
(non-blocking, never throws):

| When | `tool` | `outcome` | `metadata` (redacted, no PII, no DSA strings) |
|---|---|---|---|
| before each POST | `facebook_boost_post` | `attempted` | `{chain:'boost', planTag, step, seq}` |
| step created | same | `applied` | `{chain, planTag, step, seq, objectId}` |
| step rejected | same | `failed` | `{chain, planTag, step, seq, code, subcode}` |
| step ambiguous | same | `attempted` | `{chain, planTag, step, seq, reconciled: bool, objectId?}` |
| each rollback DELETE | `facebook_boost_post` | `applied`/`failed` | `{chain, planTag, step:'rollback:<obj>', objectId}` |
| final (by gate) | same | `applied` / `failed` / `attempted` | `{accountId, campaignId?, outcome, appliedCount, rolledBackCount, orphanedCount, currency, spendCapMinor}` |

`classifyResult(outcome)`: `complete` ⇒ `APPLIED_VERDICT`; failed and every created
object rolled back (creative excepted) ⇒ `REFUSED_VERDICT` (journal `failed`);
any `orphaned` or unreconciled ambiguous step ⇒ `ATTEMPTED_VERDICT`.
`classifyOutcome(err)` for a throw escaping the chain (bug path) ⇒ `attempted`.
Also add `planTag` to the log redaction allow-list (it is not secret).

### 1.9 Partial-failure report (`outcome:'partial'`)
Text: "Boost NOT completed: failed at <step> (<code>/<subcode>: <user_message>). Rolled
back: <list>. Left behind (all PAUSED, not spending): <list with ids and reasons>. Find
them in Ads Manager by searching 'fbmcp:<plan8>' and delete them, or call
facebook_delete_ad_object on each id." `next_steps` lists the delete calls.
