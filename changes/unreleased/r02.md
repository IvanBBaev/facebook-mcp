### Changed

- **BREAKING: free-text moderation verbs are plan-first (operator-visible behaviour change).** `facebook_reply_to_comment`, `facebook_comment_on_post` and `facebook_edit_comment` now always return a preview first and post only on `apply:true` bound to that preview's `plan_id`, as `facebook_reply_and_hide_comment` already did. Neither the `moderation` package's `apply` default nor `FB_WRITE_MODE=apply` skips the preview any more. Hide, unhide, like, unlike, block and unblock carry no text and keep the one-call `apply` default; `FB_WRITE_MODE=plan` still forces plan mode on every verb. Agents and scripts that replied in one call must now make two: preview, then apply with the returned `plan_id`.

### Security

- **A prompt-injected comment can no longer publish as the Page in one call (SEC-01).** Moderation text is usually drafted while reading strangers' comments; binding every public reply, comment, edit and `attachment_url` to a previewed plan stops a single steered call from posting it. `SECURITY.md` now recommends a read-only profile (`FB_PACKAGES_READONLY`) or a client with elicitation for sessions that read comments or the inbox. Plan-first is not a human confirmation: both steps are still model calls.
